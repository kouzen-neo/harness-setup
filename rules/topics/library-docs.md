# Library documentation

- Use a documentation MCP server (for example Context7, if it is registered) for current documentation of any library, framework, SDK, API, or CLI tool: syntax, configuration, version migration, setup. Do this even for well-known libraries, and prefer it over web search for library docs.
- Resolve the library first, then fetch the docs for the question. Also use it to confirm the latest stable version when choosing a tech stack.
- Do not use it for general programming questions or refactoring that does not depend on a library API.
- If the server is disconnected or needs sign-in, tell the owner and fall back to the official docs.
